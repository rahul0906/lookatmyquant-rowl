## 4. Installation metadata and temporary paths

`lookatmyquant.egg-info/` was generated by editable package installation. These files do not implement model execution and should not be edited as source. They describe packaging state at generation time and can be regenerated by installation. The documentation follow-up's full staged whitespace check reported trailing spaces in `PKG-INFO`; the generated metadata and its staging were preserved. New/updated documentation passed its own checks. `.venv/` is the local dependency environment and is ignored; its thousands of dependency files are not optimization source files.

Historical native prototypes wrote `.mlxfn` graphs, `.safetensors` fixtures, JSON timings and compiled executables under temporary export directories such as `/private/tmp/inkling-native-layer`. They require native MLX and compatible headers/libraries. These temporary files are not production dependencies and their continued presence is not assumed. The isolated `/private/tmp/inkling-mlx-0323` environment was used only for the older-library experiment.

The owned `/private/tmp/inkling-m3-target.gputrace` payload was removed after its metadata and size manifest were saved. The manifest is listed below; it cannot replay the capture. No model-weight files were edited.

## 5. How to read measurement files

| Type | Meaning |
|---|---|
| Raw `.json` | Saved outputs, settings, timing samples and/or memory data; schema differs between historical tools. Completed execution is separate from acceptance. |
| `*-analysis.json` | Derived paired/parity/acceptance report. Most general reports require checking the threshold in the plan; exact-cache reports include an explicit cache gate. |
| `.log` | Captured command output, errors or printed analysis; useful for interruptions and release checks. Some earlier commands were retained only as JSON/chat history, so not every JSON has a log. |
| `.server.log` | stdout/stderr from the owned live-test server child, separate from the client-test log. |
| `.prof` | Binary cProfile data for Python/native call attribution; CPU attribution includes native/GPU waiting and is not GPU-duration evidence. |
| Pipeline/check `.json` | Command arguments where recorded, exit codes and wall times; does not itself establish performance acceptance. |

Older partial files can still say `running` after a killed process. Newer normal-exit interruption handling does not rewrite that historical data. The initial sampled and combined long cache analyses remain false; their larger reruns are separate files.

## 7. Maintenance notes

Production edits for future cache work normally involve `exact_prompt_cache.py`, `generate.py`, `model.py`, `server.py` and their tests. Benchmark-only hypotheses belong in a dedicated benchmark process; do not treat historical `--candidate-*` commands as recommended serving settings. The GPU prefix-matcher switch/path was removed after rejection, so its historical command is not supported by the current harness.

Preserve measurement-time hashes and original failing/partial JSON. Create separately named reruns and derived reports. Update this map when files are added or removed, and use the final-results/ledger dispositions to decide acceptance. No benchmark rerun is needed for documentation-only changes.
